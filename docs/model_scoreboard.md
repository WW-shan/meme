## Notes

- v75b used `profit_path` behavior cloning, `min_policy_hold_seconds=60`, `trailing_start_pct=0.35`, `trailing_stop_pct=0.12`, `stop_loss=-0.25`, `entry_delay_seconds=1`, `exit_delay_seconds=4`, and 10% position sizing.
- v75b is useful evidence that simply forcing longer minimum hold is not enough. The next promising direction is conditional exit logic: keep runners longer only when path/flow features justify it, while preserving fast exits for collapsing tokens.
- v76 is useful evidence that making the buy label stricter is not enough. Recent near-miss analysis found a small runner subset among high `PredReturn` rejects, but most high `PredReturn` rejects still had large downside. The next direction should be a second-stage runner filter or conditional exit policy, not a global threshold relaxation.
- v77 confirms the same shape with a softer threshold: some runner-like cases exist in high `PredReturn` rejects, but a single global quality threshold still leaves too much money on the table versus v67. The next step should be a dedicated runner classifier or conditional exit path, not another threshold sweep.
- v78 confirms that using average-path return as the primary buy label is too restrictive. It raises apparent win rate but collapses trade count and turns both walk-forward and stress replay negative, so the next candidate should separate runner discovery from dump avoidance instead of replacing the main buy label with an average-path target.
- The latest-calibrated v67 `min_entry_score=35/40` sweep confirms entry-value gating is useful as a risk filter but not sufficient as a standalone improvement. It improves validation and harsh-stress robustness, but final return stays below the accepted hold75 baseline.
- A quick validation falsification of lower thresholds showed that `buy_threshold=0.95/0.94/0.93` plus simple young-token, volume, and volatility filters admits too many weak signals. The `0.95` and `0.94` variants lost money with extreme drawdown, while `0.93` needed 1281 validation trades and still had `-64.4315%` max drawdown. Do not lower the global threshold without a learned second-stage gate.
- A 2026-05-17 post-restart near-miss check again rejected global threshold lowering: seven `prob>=0.93` rejects with available 300s paths mostly had only `0-8%` max upside before falling `-25%` to `-59%`; the best short spike (`CC`) reached about `+34%` but later faded to about `-22%`. This points to conditional runner/exit modeling, not broader entry.
- Early trailing was falsified as a simple fix for short spikes. On the current latest-calibrated validation split, v67 hold75 baseline returned `195.7659%`; `trailing=30%/10%` returned `183.0245%`, and `trailing=25%/10%` returned `178.6817%`. Do not switch to globally earlier trailing.
- Research note: Hudson & Thames' meta-labeling writeup frames the method as a secondary model that learns when to use a primary model and describes triple-barrier labels as path-based labels rather than simple next-step direction labels. For this repo, the next viable experiment should preserve v67 as the primary model and train a second-stage take/skip or runner classifier on v67 candidate signals, using path/barrier outcomes and live execution costs. Source: https://hudsonthames.org/does-meta-labeling-add-to-signal-efficacy-triple-barrier-method/
- v67 hold60 is accepted as an exit-parameter upgrade, not a new buy model. A same-data check versus hold40 showed `267.5674%` vs `259.4872%` final return, `64.5455%` vs `59.0909%` win rate, `-21.0330%` vs `-23.7954%` max drawdown, `41.1429%` vs `30.1828%` walk-forward worst return, and stronger harsh stress replay. This matches live evidence that some profitable runners were being cut too quickly, while keeping the hard stop, trailing, and 10% sizing unchanged.
- v79 shows that a simple `live_target_hit_before_stop` barrier label with a `25%` target is too permissive for this data. It generated many low-quality entries and failed even after raising the threshold, so the next profitable direction should preserve v67's high-quality entry model and focus on conditional runner exits or second-stage filtering rather than replacing the buy target wholesale.
- v67 hold75 is accepted as a latest-calibration exit-parameter upgrade, not a new buy model. Under 2026-05-17 execution calibration (`entry_delay=1`, `entry_max_fill_wait=4`, `entry_price_protection=7.9784%`, `exit_delay=7`, `exit_max_fill_wait=8`) and explicit `max_hold_seconds=300`, validation improved from hold60 `182.7473%` to `195.7659%` return, `61.0000%` to `63.0000%` win rate, `44.0271%` to `48.8485%` walk-forward worst return, and harsh execution from `-0.5943%` to `15.7276%`. Final return improved from `187.7406%` to `194.7110%`; final drawdown and walk-forward were slightly worse but remained within gate, with harsh stress still positive.
- v80 shows that token-balanced sample weighting is not a standalone meta-labeling fix. It can surface many more trades and inflate headline return, but without a strict second-stage gate it overfits active token clusters and destroys final walk-forward robustness. Any future token-balanced experiment must constrain the primary threshold/trade count or use it only inside a true v67-candidate take/skip gate.
- A 2026-05-18 fast falsification of `buy_sample_weighting=recency_decay` on the target-hit60 / entry-value stack did not beat v84. With `max_samples_per_token=20`, `buy_recency_half_life_hours=36`, and `catboost_iterations=100`, the holdout run reached `65.8447%` final return, `-10.3151%` max drawdown, `4.2660%` WF worst return, `22` trades, `5.6425%` harsh friction, and `-6.9837%` harsh execution. The implementation is useful, but the current weighting curve is not a baseline improvement.
- v67 `entry_value` / `min_entry_score=40` is accepted as a runtime gate upgrade, not a new buy model. It uses the already shipped diagnostic entry-value model as the live `PredReturn` filter. On the 2026-05-18 current-data full validation it improved return from `193.4369%` to `201.5949%`, win rate from `63.0000%` to `66.2162%`, and WF worst return from `47.8686%` to `64.1369%`. On final it improved return from `187.9662%` to `189.6565%`, win rate from `61.9565%` to `67.6923%`, max drawdown from `-21.5063%` to `-15.6950%`, and harsh execution from `13.6437%` to `35.1696%`. The earlier 2026-05-17 `min_entry_score=40` rejection was under the older same-data hold75 check without this final current-data acceptance pass.
- A follow-up entry-protection sweep on the same v67 runtime gate showed that widening `entry_price_protection_pct` materially improves live-sized replay and stress. The best nearby offline compromise was `entry_price_protection_pct=0.18` with `min_entry_score=45`, which reached `220.2125%` final return, `-16.7280%` max drawdown, `40.3773%` WF worst return, and positive harsh stress (`74.6735%` harsh execution, `63.4903%` harsh friction). It is better than the accepted `min_entry_score=40` runtime gate on return, walk-forward, and stress, but the live bot was left unchanged per user instruction and should be restarted into this candidate later.
- The latest v84 hold-window sweep promotes `max_hold_seconds=420`, not `600`. The 600s point has higher raw final return, but lower win rate and weaker harsh stress; 420s is the current best risk-controlled runtime baseline for the v84 model.
- The v84 `min_policy_hold_seconds=60` transfer test was rejected. The v86b-specific hold60 improvement does not generalize to the stronger v84 model; v84 stays at `min_policy_hold_seconds=45`.
- The v86b delay-robust probe confirms that path-aware labels and profit-path behavior cloning can improve over the live v67 baseline, but not enough to beat v84. Within v86b, the profitable adjustment was increasing `min_policy_hold_seconds` from `45` to `60` while keeping `min_entry_score=35`; raising `min_entry_score` improved risk but cut too much return, and shortening the hold floor to `20` degraded both return and drawdown.
